# 宝贝早餐实施任务清单

## 1. 使用说明

本任务清单按可交付里程碑组织，目标是优先打通“计划生成 -> 今日查看 -> 做菜执行 -> 儿童反馈 -> 推荐回流”的主链路。每个任务包含目标、关键产出和验收要点，适合直接进入排期与开发。

## 2. 总体实施顺序

1. 项目骨架与基础设施
2. 账户、家庭、菜品、库存、计划主链路
3. AI 编排与反馈画像闭环
4. 管理后台、离线、提醒、部署增强

## 3. 里程碑一：MVP 主链路

### 3.1 工程初始化

- [ ] 创建前端工作区：`apps/pwa`、`apps/admin`、`packages/shared`
- [ ] 创建后端工程：Spring Boot 单体服务基础骨架
- [ ] 配置统一环境变量、日志、代码规范、基础 CI
- [ ] 配置本地开发 `docker compose`，包含 MySQL、Redis

交付物：

- 前后端可启动骨架工程
- 本地开发环境文档

验收要点：

- PWA、Admin、API 三个服务可本地启动
- MySQL、Redis 能通过统一配置接入

### 3.2 认证与家庭上下文

- [ ] 实现用户名密码登录
- [ ] 设计并实现 `user`、`family`、`family_member` 基础表
- [ ] 实现 JWT 鉴权和家庭上下文解析
- [ ] 实现当前角色切换接口和前端状态管理

交付物：

- 登录接口与登录页
- 家庭上下文中间件

验收要点：

- 用户登录后可读取当前家庭和当前角色
- 家长与儿童角色切换后前端主题即时变化

### 3.3 家庭成员管理

- [ ] 实现家庭成员列表、创建、编辑接口
- [ ] 支持角色、年龄、头像、过敏信息、饮食限制维护
- [ ] 在 PWA 中实现家庭成员查看与切换
- [ ] 在 Admin 中实现家庭成员管理页

交付物：

- 家庭成员管理 API
- PWA 成员切换组件
- Admin 成员管理页面

验收要点：

- 家长可维护成员资料
- 推荐相关接口可获取过敏和饮食限制信息

### 3.4 菜品中心基础能力

- [ ] 设计并实现 `dish`、`dish_step`、`dish_media`、`ingredient`、`dish_ingredient` 表
- [ ] 实现菜品 CRUD、步骤维护、标签维护
- [ ] 实现媒体上传和默认封面图逻辑
- [ ] 预置一批系统菜品种子数据
- [ ] 在 Admin 中实现菜品列表和编辑页

交付物：

- 菜品中心 API
- 菜品管理后台页面
- 初始菜品数据脚本

验收要点：

- 可创建完整菜品，包含食材、步骤、标签和媒体
- 未上传封面图的菜品展示默认图

### 3.5 库存与购物清单基础能力

- [ ] 设计并实现 `inventory_item`、`shopping_list`、`shopping_list_item` 表
- [ ] 实现库存列表、增减、更新接口
- [ ] 实现根据菜品配方计算库存需求
- [ ] 实现当前购物清单查询接口
- [ ] 在 PWA 中实现库存页和购物清单页

交付物：

- 库存管理 API
- 购物清单基础 API
- PWA 库存与清单页面

验收要点：

- 家长可手动维护库存
- 系统可根据计划和库存差量输出购物项

### 3.6 节假日与计划主链路

- [ ] 设计并实现 `holiday_calendar`、`weekly_plan`、`daily_meal`、`daily_meal_dish` 表
- [ ] 实现节假日批量维护接口
- [ ] 实现工作日集合计算器
- [ ] 实现规则版周计划生成器，先基于菜品标签和约束输出可用计划
- [ ] 实现计划确认、替换单天、锁定单天、拖拽排序接口
- [ ] 在 PWA 中实现周计划页面和今日早餐页面

交付物：

- 周计划主链路 API
- 今日早餐与周计划前端页面
- Admin 节假日配置页面

验收要点：

- 家长可生成 7 天或工作日早餐计划
- 节假日配置能影响计划生成结果
- 今日早餐页面能展示菜品列表和步骤入口

### 3.7 做菜步骤引导

- [ ] 实现菜品详情页和步骤页
- [ ] 实现沉浸式逐步引导模式
- [ ] 实现烹饪会话记录与完成制作确认接口

- 步骤引导页面
- 制作确认 API

验收要点：

- 家长可按步骤查看做菜流程
- 确认制作后库存按配方扣减

## 4. 里程碑二：AI 与反馈闭环

### 4.1 AI 编排基础设施

验收要点：

- 系统可配置并调用至少一种外部模型

验收要点：

验收要点：
